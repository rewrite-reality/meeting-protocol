# meeting-protocol

Сервис автоматической расшифровки, диаризации и протоколирования производственных совещаний на основе открытых нейросетевых моделей. Выпускная квалификационная работа, ЮУрГУ, ВШЭКН.

Текущий этап: **M0 – каркас**. Поднимается стек, работает healthcheck, настроена непрерывная интеграция. Функции обработки аудио появятся на следующих этапах.

## Что делает сервис

Конвейер обработки записи совещания:

1. Приём аудиофайла (WAV, MP3, FLAC, M4A, OGG) и постановка задачи в очередь.
2. Нормализация сигнала, подавление производственных шумов, выделение речи.
3. Распознавание речи с учётом отраслевой терминологии.
4. Диаризация дикторов и привязка реплик к сотрудникам.
5. Извлечение поручений локальной языковой моделью: действие, ответственный, срок.
6. Формирование протокола по ГОСТ Р 7.0.97-2016 в форматах DOCX и PDF.
7. Передача поручений в корпоративные трекеры по REST API.

Развёртывание полностью локальное, без обращений к внешним облачным сервисам.

## Стек

| Слой | Технологии |
|---|---|
| API | Python 3.11, FastAPI, Pydantic |
| Данные | PostgreSQL 16, Redis 7, MinIO |
| Очереди | Celery + Redis |
| ML | faster-whisper, pyannote.audio, DeepFilterNet, Silero VAD |
| LLM | открытая модель с квантованием, вывод в строгой схеме JSON |
| Инфраструктура | Docker, Docker Compose, GitHub Actions |

## Быстрый старт

```bash
cp .env.example .env
docker compose up --build
curl http://localhost:8000/health
```

Ожидаемый ответ: `{"status":"ok","service":"api"}`.

Локальный запуск без Docker:

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
pytest -q
```

## Структура

```
app/            FastAPI-приложение: роуты, конфигурация
worker/         Celery-воркер: фоновые задачи обработки
tests/          pytest-тесты
docs/           архитектура и решения
.github/        непрерывная интеграция
```

## Ветки и вехи

| Ветка | Веха |
|---|---|
| `main` | всегда рабочая версия, прямые пуши запрещены |
| `feat/m0-bootstrap` | каркас сервиса, compose, CI |
| `feat/m1-upload` | приём и хранение аудио, очередь задач |
| `feat/m2-asr` | распознавание речи |
| `feat/m3-diarization` | разделение дикторов |
| `feat/m4-action-items` | извлечение поручений |
| `feat/m5-gost-docx` | протокол по ГОСТ |
| `feat/m6-rbac` | роли, аудит, нагрузка |

Ветка живёт до закрытия вехи, затем вливается в `main` одним squash-коммитом и удаляется. Веха отмечается тегом `v0.N.0-mN`.

## Правила репозитория

1. В репозиторий не попадают реальные записи совещаний, персональные данные и веса моделей.
2. Каждый merge в `main` проходит через pull request и зелёный CI.
3. Коммиты в формате `тип(область): описание`, типы: feat, fix, docs, chore, test, refactor.
4. Версии зависимостей фиксируются в `requirements.txt`.
