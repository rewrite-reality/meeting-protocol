# Архитектура

## Назначение

Сервис принимает аудиозапись совещания и возвращает протокол: стенограмму с разделением по дикторам, список поручений и документ по ГОСТ Р 7.0.97-2016. Развёртывание полностью локальное, без обращений к внешним сервисам.

## Компоненты

| Компонент | Ответственность |
|---|---|
| `api` | приём файлов, статусы задач, выдача результатов, права доступа |
| `worker` | фоновые задачи: нормализация, шумоподавление, распознавание, диаризация, извлечение поручений, сборка документа |
| `postgres` | метаданные совещаний, сегменты стенограммы, поручения, справочник сотрудников |
| `redis` | брокер задач и результаты |
| `minio` | аудиофайлы и готовые документы |

## Поток обработки

1. Клиент загружает файл, `api` сохраняет его в MinIO и создаёт запись совещания в статусе `uploaded`.
2. `api` публикует задачу в очередь и возвращает идентификатор.
3. `worker` последовательно выполняет этапы конвейера, обновляя статус.
4. Обработка тяжёлых моделей идёт последовательно: загрузка акустической модели, затем языковой. Параллельный запуск не планируется из-за ограничения видеопамяти.
5. Готовый протокол сохраняется в MinIO, метаданные и структура остаются в Postgres.

## Ограничения

Один графический ускоритель объёмом 24 ГБ, операционная система семейства Linux в контейнерах, отсутствие исходящих соединений во внешние сети.
